# foundryvtt 1.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the `condense-scenes-to-levels` and `rig-hazard-region` skills to the foundryvtt plugin, fold the 2026-11-11 testing lessons into `live-test`, and release it as 1.2.0.

**Architecture:** Each skill is one `SKILL.md` in live-test's shape (frontmatter, Context, named Commands blocks, numbered Steps, Guardrails, source footer). Each is written test-first per superpowers:writing-skills: a subagent runs an application scenario without the skill (RED), then with it (GREEN), scored against a fixed checklist. The hazard skill's command blocks are also run live once in Rolara-Wednesday.

**Tech Stack:** Markdown skills; Foundry v14 build 368, dnd5e 5.3.3, Midi-QOL 14.0.12, Perceptive 6.0.8; the built-in browser's `javascript_tool`.

**Spec:** `docs/superpowers/specs/2026-11-11-rig-hazard-region-design.md` (hazard skill). The condense skill and the live-test lessons follow the handoff brief's "Condense" and "Testing lessons" sections, copied into the checklists below.

## Global Constraints

- No em dashes, and no double hyphen used as a dash, in anything written.
- Write each instruction as the action to take, then why it is right.
- Match `foundryvtt/skills/live-test/SKILL.md`: frontmatter with `name`, `description` ("Use when..."), `argument-hint`, `allowed-tools`; then Context, Commands (blocks named in bold, each tagged with the tool that runs it), Your Task > Steps (numbered), Guardrails, and the source footer.
- Edit only this repo's copy, never `~/.claude/plugins`.
- Live checks run only in Rolara-Wednesday, on a scratch scene that is viewed and never activated, with nobody else connected.
- Data repo commits use explicit paths only.
- Push nothing without the user's word.

## Review Focus

1. A Midi rule firing an activity with an area template (the statue's cone) may open a placement prompt on the GM client or stall; the user expects the trap to go off or the skill to say what to do. Pinned in Task 2, Step 5.
2. A test token placed by displace inside a Midi region sets it off (Token Enter), so tests start outside. Pinned in Task 2, Step 5.
3. A Test Player moving in: the activity runs through Midi's socket on the GM, and the save prompt must reach the player. Pinned in Task 2, Step 5.
4. A region whose `levels` or elevation doesn't match the floor never fires. Pinned in Task 2, Step 5 (fires on its level, not from another level).
5. dnd5e re-rolls HP on copied unlinked tokens. Pinned in Task 1's checklist (C9).

### Task 1: condense-scenes-to-levels

**Files:**
- Create: `foundryvtt/skills/condense-scenes-to-levels/SKILL.md`
- Test notes: `<scratchpad>/skill-tests.md` (deleted when the job ends)

**Interfaces:**
- Produces: the skill `foundryvtt:condense-scenes-to-levels`, argument hint `<world> <source scenes> <base scene>`. It relies on live-test's WHO, START, JOIN, READY and POPUPS by name instead of repeating them.

Checklist (score every RED and GREEN run against it):
- C1 Checks every source scene's size, grid and padding match the base before copying anything.
- C2 One Level per floor: 9 ft tall, 10 ft apart, negatives allowed below ground (Dungeon -20..-11, Basement -10..-1), named by the user's pattern ("Collector's Wizard Tower (Library)"), `background.src` set to that floor's map.
- C3 Assigns the base scene's own walls and lights to the base level (`defaultLevel0000`), because an empty `levels` means every level.
- C4 Sets `levels` explicitly on every copied document, because every source scene's only level is also `defaultLevel0000`.
- C5 Copies walls with `toObject()`, deletes `_id`, sets `levels: [levelId]`, and verifies a sorted signature of coords, move, sight, light, sound, door, ds and dir against the source.
- C6 Sets each light's `elevation` to its level's bottom.
- C7 Perceptive: deletes orphan helpers (`flags.perceptive.isPerceptiveWallFlag`) on rebuilt levels, repoints dangling doors' `flags.perceptive.LockPeekingWallIDsFlag` at the copied helpers, resets helper coords to the door's, re-checks the wall count against the source.
- C8 Tokens: copied with `level`, `elevation` = level bottom + old elevation, `keepId`, stripping `_movementHistory` and `_regions`.
- C9 Diffs each unlinked token's `delta` against the source with `foundry.utils.diffObject` and restores it (dnd5e re-rolls HP).
- C10 Asks which duplicate to keep when a linked actor has tokens on two source scenes.
- C11 Combat: checks active effects for the old combat id; creates a new Combat on the base scene with `round` and `turn` at create time, copies `flags`, creates combatants with `keepId`, verifies turn order, then deletes the old combat.
- C12 Stairs: Teleport Token region pairs, same coordinates on both floors, relative placement, choice on, 1500 ms fade, named "NNN Stairs ^" (lower) and "NNN Stairs v" (upper), never two overlapping squares on a middle floor, each region's elevation [floor, floor + 5), tested both ways with 1x1 and 2x2 tokens.
- C13 Views the token's level (`scene.view({level})`) before moving or updating a token through the API.

### Task 2: rig-hazard-region

**Files:**
- Create: `foundryvtt/skills/rig-hazard-region/SKILL.md`

**Interfaces:**
- Consumes: live-test by name for sign-in and the two-sided test; `Data/macros/INDEX.md` for recorded extras.
- Produces: the skill `foundryvtt:rig-hazard-region`, argument hint `<world> <hazard or trap> <where> [level]`.

Checklist:
- H1 Proposes the full setup in one message and creates nothing before the user's OK.
- H2 Picks the activity for the party's level band ("Trigger (5-10)" for level 7), and asks when an item has bands and no level was given.
- H3 Uses Midi Region Activity (`midi-qol.regionActivity`) with rules matching the item's trigger (the statue: `entry` and `turnStart`, `oncePerTurn` on).
- H4 Sets `dispositionFilter` to 0 and keeps `excludeSource` on, with `sourceActorUuid` and `sourceItemUuid` from the Multitrap token.
- H5 Takes the spot from a region the user drew (adopting it) or a token or tile the user names, never from the map art; places a hidden Multitrap token on the region's level (on the statue for the statue); sets the region's `levels` and shallow elevation.
- H6 Says the cone reaches only the creature that stepped in, and offers covering the cone as an extra.
- H7 Searches `macros/INDEX.md` for a recorded extra by hazard name and offers it (quicksand: the recorded script, not a rebuild).
- H8 For a new extra: describes it, waits for approval, tests with live-test on both sides, then saves to `Data/macros/` with the house header, adds the INDEX row, and commits in the Data repo with explicit paths.
- H9 Tests by placing tokens outside the region and dragging them in, moved by GM and by Test Player, walking in and walking through.
- H10 Treats flyers as the GM's call: no flyer-skipping script.
- H11 Stops and asks when anyone but the GM is connected.
- H12 Leaves touch hazards and ongoing effects (sinking, escapes, suffocation) manual, and asks where to get a Multitrap when the world has none.

### Task 3: live-test testing lessons

**Files:**
- Modify: `foundryvtt/skills/live-test/SKILL.md` (Commands, Steps 3 and 6, Guardrails)

Checklist:
- L1 Views the token's level (`scene.view({level})`) before moving or updating a token through the API; otherwise `includedInLevel` throws "Cannot read properties of undefined (reading 'parent')".
- L2 Places tokens with `token.move([{x, y, action: "displace"}], {constrainOptions: {ignoreWalls: true}})`, because `update({x, y})` is wall-constrained in v14; a displace skips Move In traps.
- L3 Drags tokens with `left_click_drag` at screen coordinates from `canvas.stage.worldTransform`, because arrow keys don't reach the canvas.
- L4 Knows Execute Script behaviors run on every client and the active GM may be the user's own GM client; tests the GM path by briefly overriding `game.user.isActiveGM` and calling the behavior's `_handleRegionEvent` with a fake event.
- L5 Gives every test token an actor, because DAE's updateToken hook throws on actorless tokens.
- L6 Keeps the GM tab signed in and uses the 127.0.0.1 tab for the Test Player, never signing out and in again in one tab.
